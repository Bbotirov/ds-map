# Архитектура ds-map

## Слои

```
харнес  ──JSONL tail──►  dsmapd  ──WS/JSON──►  окно ds-map
                        │
                        ├─ classify()   → станция + метка
                        ├─ redact()     → только имена, никогда содержимое
                        └─ bus          → подписчики
```

Журнала на диске нет: отладочные строки идут только в stdout лаунчера и панели
(`[ds-map] …`), и в них не бывает содержимого — только имена событий и тайминги.

**Правило слоёв:**
- `core/` не знает про Electron, сеть и файловую систему.
- `daemon/` не знает про DOM.
- `ui/` не знает, откуда пришли события.
- `extension/` не знает ни про что из перечисленного: это тонкая обёртка,
  которая только находит CLI и запускает его в терминале.

Это позволяет тестировать всё, кроме окна, без окна.

## Компоненты

### `src/core/events.ts`
Схема событий ds-map (JSONL, v:1). Типы: `session.start`, `prompt`, `model.step`,
`tool.start`, `tool.end`, `answer`, `context.update`.

### `src/core/classify.ts`
Классификатор: команда → станция. Чистые функции, без побочных эффектов.
Главное правило: классифицируем по ИМЕНИ команды, а не по тому, что она делает.

### `src/core/redact.ts`
Приватность: только имена. `fileLabel`, `urlLabel`, `commandLabel`, `safe` (fail-open).
Пути сокращаются до имени файла, URL — до хоста, команды — до имени утилиты;
аргументы не попадают в подпись.

### `src/core/route.ts`
Маршрутизация: сырые события DSH → события ds-map.

### `src/daemon/bus.ts`
Шина событий: подписчики получают события ds-map.

### `src/daemon/session.ts`
Хвост сессионного JSONL (`session.v4.jsonl`). Ищет последнюю сессию для cwd,
парсит строки, публикует в шину. Типы записей DSH: `session`, `turn/*`, `step/*`,
`user/message`, `assistant/message`, `tool/call`, `tool/result`, `job/*`,
`session/title`.

### `src/daemon/server.ts`
Локальный HTTP + WS сервер на `127.0.0.1` со случайным портом и токеном.
Токен проверяется на каждом запросе, файлы порта/токена удаляются при выходе.

### `src/cli.ts`
Лаунчер: `dsmap run -- <команда>` и `dsmap doctor`. Поднимает сайдкар в своём
процессе, запускает харнес и окно панели, по SIGINT/SIGTERM гасит всех детей и
убирает файлы. `doctor` проверяет Node, Electron, сборку, наличие `dsh`,
порт/токен и состояние окон.

### `src/shared/config.ts`
`.dsmap-config.json` (в `.gitignore`) и переменные окружения. Чтение терпимо к
BOM в JSON, битый конфиг не роняет ни лаунчер, ни панель (fail-open).

### `src/ui/main.ts`
Electron main: окно, WS к сайдкару, пристёгивание к окну-якорю, слежение за
живучестью лаунчера. Убийство панели не влияет на харнес — они в разных
процессах и связь только по localhost.

### `src/ui/launcher-watch.ts`
Признак «лаунчера больше нет» — молчание его порта: опрос `http://127.0.0.1:<port>/`
раз в секунду, `grace = 3` неудачи подряд. Два других способа на Windows
оказались неверны: `kill(pid, 0)` видит мёртвый PID живым (дети держат handle
родителя), а EOF на stdin срабатывает сразу (Electron — GUI-подсистема).
Запас попыток гасит кратковременные сбои localhost, а не убитый процесс.

Два probes различаются нарочно. `probeSidecar(port)` — GET **без** токена: его
задача лишь «порт отвечает или нет», а `403` от нашего сайдкара как раз значит
«отвечает». `probeEndpoint(endpoint)` — GET **с** токеном и принимает только
`res.ok`: здесь вопрос «на этом порту всё ещё сидит тот самый сайдкар», и чужой
сервер, поднявшийся на освободившийся порт, должен дать false.

### Уборка порта и токена (§12.4: «ничего не хранится между сессиями»)
`taskkill /F` не отдаёт процессу ни SIGINT, ни exit-колбэков, поэтому после
жёсткого убийства лаунчера в `~/.dsh/` остаются `dsmap-port.txt` и
`dsmap-token.txt`. Убирают их два независимых живых свидетеля — тот, кто остался
в processes:
- панель (`src/ui/main.ts` → `clearDeadSidecar()`): на `port-dead` перечитывает
  эндпоинт, прогоняет `probeEndpoint` и, только если порт вправду молчит, снимает
  оба файла перед `app.quit()`;
- расширение (`extension/src/endpoint.ts` → `clearStaleEndpoint()`): на
  `onDidCloseTerminal` (терминал закрыли вручную или окно перезагрузилось —
  `dispose()` снимает дерево без Ctrl-C) делает пробу и удаляет файлы, сравнив
  их содержимое с прочитанным: за время пробы мог подняться новый лаунчер, и
  чужую пару трогать нельзя.

Оба работают по правилу «сначала проба, потом удаление»: живой сайдкар — не мусор,
и удалять его файлы нельзя ни при каком закрытии терминала.

### `src/ui/window.ts` + `src/ui/window-watcher.ps1`
Поиск окна-якоря и его координаты. Якорь задаётся тремя способами (в порядке
надёжности): точный `DSMAP_HWND` консоли лаунчера, `DSMAP_TITLE` (подстрока
заголовка — нужно, когда UI харнеса живёт в браузере), дерево PID
(`DSMAP_PID_LIST`). Наблюдатель — отдельный PowerShell-процесс, который пишет
в stdout строки состояния; `DSMAP_OWNER_PID` гарантирует, что он умрёт вместе
с панелью и не останется сиротой. Координаты из `GetWindowRect` уже приведены
к 96-TPI DIP.

Формула пристегивания: `x = anchor.x + anchor.width + 8`, `y = anchor.y`,
`h = anchor.height`, `w = clamp(420, 320, 560)`. Без якоря — правый край экрана.

### `src/ui/renderer/map.ts`
SVG карта-радар 460×430. Геометрия из lot-map (MIT):
W=460, H=430, CX=230, CY=212, RX=176, RY=164, NODE=22, CORE=40.
Пульсы (PULSE_MS=800), маршрут (TRAIL_HOLD_MS=40000, TRAIL_FADE_MS=20000),
кольцо контекста, часы.

`STATION_ICONS` — по одному набору штрих-путей на станцию (±9 единиц, центр в
`(0,0)`), `icon()` рисует их поверх узла с `fill="none"`, `stroke-width 1.25`,
скруглёнными концами. Цвет глифа считает `glyphColor()`: ошибка → красный,
активная станция → свой hot, `memory` с ненулевым счётчиком → бирюзовый,
иначе — обычный цвет подписи. Подписи узлов печатаются с `paint-order="stroke"`
(гало в цвет фона), поэтому остаются читаемыми поверх колец и маршрута.
Иконки рисуются и в покое (`drawNodeBase`), и в момент свечения
(`drawStationFx`) — состав узла не меняется от состояния, только цвет.

### `src/ui/renderer/feed.ts`
Лента событий: последние 16 строк, ●/·/✕/◆ символы, сворачивание подряд.

### `src/ui/renderer/app.ts`
Рендерер: чистый SVG + минимум DOM. IPC через preload, анимация через rAF
(не более 30 fps, остановка в покое).

### `src/ui/preload.ts`
contextBridge с узким API: `onEvent`, `getConfig`, `setConfig`.

### `src/ui/index.html`
HTML оболочка с тулбаром (тема, язык, reduced motion, статус).

## Расширение VS Code (`extension/`)

```
extension/src/extension.ts    команды dsMap.start|stop|doctor, статус-бар, терминал
extension/src/cli-lookup.ts   где взять dist/cli.js: настройка → DSMAP_BIN →
                              workspace → bundled → глобальный npm → ~/.dsh/dsmap
extension/package.json        манифест Marketplace (publisher bbotirov)
extension/test-runner/run.js  прогон в настоящем хосте VS Code
test/mocks/vscode.ts          тот же API с записью вызовов — для юнит-тестов
scripts/package-extension.mjs tsc → PNG-иконка через @resvg/resvg-js → vsce package
```

Правило: расширение не читает сессии и не открывает сеть. `start` пишет в
терминал `node "<cli>" run -- <harnessCommand>`, `stop` отправляет настоящий
байт `0x03` (в VS Code это node-pty, поэтому SIGINT доходит; в Windows
Terminal/conpty синтетические console events не доставляются — см. DISCOVERY).
Сама панель живёт в отдельном Electron-процессе: закрыть её — харнес работает.

## События

```jsonl
{"v":1,"t":"session.start","ts":...,"session":"s_...","model":"...","cwd":"..."}
{"v":1,"t":"prompt","ts":...,"chars":214}
{"v":1,"t":"model.step","ts":...,"context":{"used":18400,"max":128000}}
{"v":1,"t":"tool.start","ts":...,"id":"call_1","name":"read","station":"files","label":"src/app.ts"}
{"v":1,"t":"tool.end","ts":...,"id":"call_1","status":"ok","ms":400}
{"v":1,"t":"answer","ts":...,"ms":8000}
```

UI игнорирует неизвестные `t` и не падает. Любая ошибка в маппере ловится
локально (fail-open).

## Тесты

`pnpm test` — vitest; для расширения `vscode` алиасится на `test/mocks/vscode.ts`
(`vitest.config.ts → resolve.alias`), поэтому команды расширения проверяются без
хоста. Прогон в настоящем хосте — отдельный шаг: `Code --extensionTestsPath`.
Покрытие `core/` держим не ниже 80%.

## Приватность

Только имена. Никогда содержимое. Никаких сетевых запросов наружу.
Сервер только на `127.0.0.1`. Токен в файле с правами `600`.
Ничего не хранится между сессиями.
